## Small archive overlap and augmentation

The archive's `scripts/01_download.py` calls `snapshot_download` without a revision. The exact upstream revision of that ZIP therefore remains unverified. Its preparation script assigns `src_index` after concatenating sorted source parquet shards. In the 9,000 small-ZIP train+validation source indices, all indices are present either in retained v2 train/validation/synthetic-test manifests or the v2 quarantine list. In particular 522 small-train and 100 small-validation records match quarantined source indices. Thus there are zero **previously unseen source indices** in this comparison; it is not yet a verified count of distinct novel images because ZIP revision/order and all image identities are not independently established. Quarantined rows do not become eligible training data merely because their indices are known.

All 1,098 small-train/v2-validation and 954 small-train/v2-synthetic-test candidates were compared as images after resizing the v2 PNG to 256 pixels with LANCZOS. Every pair was within a mean absolute RGB error of 5/255 of its prepared JPEG. This is strong leakage evidence and a conservative review threshold, not a mathematical proof of identity. Do not mix this small archive's train split into v2 training while using the same holdouts. Per-pair results: `artifacts/small-v2-holdout-image-comparisons.csv`; procedure and summary: `artifacts/audit_small_images.py` and `artifacts/small-image-audit-20261104.json`.

Checking the archive manifests and expected member names found one original plus two augmentation rows per train source index, no missing/mismatched parent/path entries, and no source index shared by the small train and validation manifests. This checks metadata and paths, not a visual inspection of all augmented images. Keep each parent and its augmentations in one group if a future snapshot uses them; prefer on-the-fly augmentation. No new snapshot or holdout was adopted.

## Reader and smoke evidence

`new_data/zip_dataset.py` adds an experimental adapter based on the existing `FurnitureDataset` preprocessing and tensor/label contract. `new_data/config.example.json` supplies archive/manifest paths through environment variables, snapshot ID, workers, shuffle, batch, seed and image-error policy. Each worker opens its own ZIP handle; it uses no disk cache, and raises on missing archives or bad images. The adapter does not create or audit snapshots, calculate a mapping, handle missing task labels, or modify the frozen training pipeline. Passing a snapshot ID alone does not certify a dataset. Actual new-data training still requires integration with the audited training/recovery workflow.

`python -m pytest -q new_data/test_zip_dataset.py --basetemp .pip-temp/new-data-loader-1104b` passed three tests: shuffled two-epoch Windows workers and isolated handles, corrupted/missing archive failures, and config/manifest reading. The first run exposed a Windows open-handle cleanup problem; the adapter was fixed and the tests rerun. The prior v2 test binding is preserved because frozen code/config/tests were not modified; the new adapter tests are separate and not part of that binding.

`python -m new_data.smoke_adapter --archive D:\Download\furniture_dataset.zip --output artifacts\new-data-v2-train-adapter-smoke-1104` checked eight index-matched, image-compared samples from v2 train only, using the class mapping built from all v2 train rows. One CPU step over four images used the existing shared-backbone/two-head model and cross-entropy losses, and confirmed a finite nonzero shared-backbone gradient. See its manifest, config and `result.json`. It is integration smoke, not an additional-data snapshot, full pilot, trained checkpoint, evaluation or research metric. The previous 128-record D: loader probe was only a mechanism check with uncontrolled cache, not a full dataset benchmark.

# ใบงานแบ่งงาน: สิ่งที่ต้องใช้คนตัดสิน (ณ 2026-11-09)

เขียนจากการตรวจไฟล์สถานะจริงใน `artifacts/` ไม่ได้รันเทรนหรือเทสต์ใหม่ รายละเอียดหลักฐานอยู่ใน `docs/10`, `docs/19`, `docs/20` และ `RELEASE_STATUS.md`

## สถานะจริง: เทรนเสร็จแล้ว ไม่ต้องเริ่มใหม่

`docs/04-implementation-status.md` เป็นฉบับเก่า (2 พ.ย.) ที่บอกว่ายังไม่ได้ฝึก ตอนนี้ล้าสมัย สถานะจริงตรวจจากไฟล์ใน `artifacts/` มีดังนี้

| งาน | สถานะ |
|---|---|
| Screening 10 backbones | เสร็จ 10/10 |
| Controlled C1–C8 | เสร็จ 24/24 |
| Single-task baseline | เสร็จ 2/2 |
| Repeated seeds | เสร็จ 8/8 |
| Selection | ตรึงแล้ว: DenseNet121 + C6 (epoch 30) |
| Robustness, synthetic test, real-source test, final ZIP | เสร็จ (`final-delivery.json`, ตรวจ checksum แล้ว) |

| Process ที่ยังรัน | ไม่มี |

ห้ามสั่ง `suite` ซ้ำโดยไม่ตั้งใจ เพราะจะสร้าง run ใหม่ซ้อนผลที่ตรึงไว้ ถ้าจะเทรนเพิ่มต้องเป็นการตัดสินใจของทีมตามหัวข้อ "เทรนต่อ" ด้านล่าง

## ผลที่มีตอนนี้ (ต้องรายงานตามนี้ ห้ามปรับให้ดูดี)

| ชุด | Type macro-F1 | Style macro-F1 |
|---|---:|---:|
| Validation (สังเคราะห์) | 0.995 | 0.240 |
| Synthetic test | 0.996 | 0.200 |
| Real-source test (ภาพถ่ายจริง, 995/863 ภาพที่ label ใช้ได้) | 0.831 | 0.028 |

Type ทำได้ดี แต่ Style แย่มาก (ใกล้เดา) โดยเฉพาะบนภาพจริง เพื่อนที่เขียนรายงานต้องเขียนข้อนี้ตรงๆ และอธิบายสาเหตุที่เป็นไปได้ ได้แก่ 37 style ที่ labels ทับซ้อนกัน, label มาจาก AI ไม่ใช่ผู้เชี่ยวชาญ, และ domain gap ระหว่างภาพสังเคราะห์กับภาพจริง

## งานที่ต้องใช้คน

### งาน A: ตรวจ near-duplicate 494 คู่ (แบ่งได้ 3 คน)
- ไฟล์: `artifacts/source-train-cross-split-review/index.html` (มีภาพ) และ `candidates-unreviewed.csv` (กรอกคอลัมน์ `decision`)
- ตัดสินแต่ละคู่เป็น `same` / `related` / `different` / `uncertain`
- แบ่งตามคู่ split: train–validation 240 คู่, train–synthetic_test 196 คู่, validation–synthetic_test 58 คู่
- ทำไมสำคัญ: ตอนนี้ v2 กักภาพที่น่าสงสัยไว้ 622 จาก 9,000 ภาพแบบเหมารวม (conservative) ผลตรวจคนจะบอกว่ากักเกินไปหรือไม่ และเป็นหลักฐานว่าไม่มี leakage
- ตัวเลือกของทีม: (1) ข้ามงานนี้และเขียนในรายงานว่าใช้ conservative quarantine ซึ่งผลเทรนปัจจุบันใช้ได้ (2) ทำครบแล้วให้ผมสร้าง snapshot v3 และเทรนใหม่ ซึ่งต้องเทรนซ้ำทั้ง suite
- ข้อควรระวัง: ห้ามให้ AI เป็นผู้ตัดสินแทน (ที่ผ่านมาเป็นแค่ AI observation ไม่ใช่การยืนยันโดยคน)

### งาน B: นโยบายชื่อ style (ผู้ตัดสินใจคนเดียว + ปรึกษาอาจารย์)
- มี 37 style เช่น `minimal`/`minimalist`, `classic`/`classical` ที่อาจเป็นสิ่งเดียวกัน
- ต้องตัดสินใจว่าจะ (ก) คงเดิมและรายงานว่า Style อ่อน, (ข) รวม/ตัดคลาสแล้วเทรนใหม่ หรือ (ค) ลดเหลือ style ที่ผู้เชี่ยวชาญยืนยันได้
- ห้ามรวมจากความคล้ายของชื่ออย่างเดียว ต้องมีเกณฑ์ที่เขียนไว้
- เกี่ยวกับงาน A และ D: ถ้าเลือก (ข) หรือ (ค) ต้องเทรนใหม่

### งาน C: ชุดภาพห้องสำหรับประเมิน end-to-end (2 คน)
- ไฟล์: `data/room-independent-review-v1/` (`review-boxes.csv`, `review-questions.csv`, `objects-proposed.csv`)
- มีแค่ภาพ Pexels 2 ภาพ กรอบร่างจาก AI 4 กรอบ ซึ่งยังไม่ใช่ ground truth และน้อยเกินกว่าจะสรุปผลได้
- งาน: ตอบคำถามในไฟล์ (ขอบเขตเก้าอี้/โซฟา/โต๊ะ), เพิ่มภาพห้องอิสระที่ license ใช้ได้ (ควรอย่างน้อยหลักสิบภาพ), วาด/ตรวจกรอบและ label ด้วยคน, จดผู้ถ่ายกับ license
- ถ้าไม่ทำ ให้เขียนในรายงานว่า room pipeline เป็นแค่ demo ไม่ใช่ผลวัดเชิงปริมาณ

### งาน D: ตรวจ label ตัวอย่างจาก ZIP (1 คน)
- ไฟล์: `artifacts/zip-label-review-v1/samples.csv` (37 แถว) และภาพ `label-samples-*.png`
- ตรวจว่า type/style ตรงภาพหรือไม่ โดยเฉพาะที่ AI ทำเครื่องหมายว่าน่าสงสัย (เก้าอี้ gaming ที่ติด `classical`, โซฟาทั่วไปที่ติด `gothic`, เตียงมีหลังคาที่ติด `scandinavian`)
- ผลที่ได้ใช้เป็นหลักฐานคุณภาพ label ในรายงาน

### งาน E: แหล่งข้อมูลใหม่ขนาดใหญ่ (ใครมีไฟล์/ที่เก็บ)
- ต้องการ `furniture_sources.zip` ครบไฟล์ (42.67 GB) บนไดรฟ์ที่อ่านได้เสถียร ลิงก์ Drive เดิมตอบ 404 และ D: เหลือที่ประมาณ 27.6 GB ไม่พอ ส่วน E: มีปัญหาสุขภาพไดรฟ์
- ตอนนี้ยังตอบไม่ได้ว่ามีภาพอิสระใหม่กี่ภาพ ห้ามอ้างตัวเลข 633,752 เป็นจำนวนภาพที่ฝึกได้
- ZIP ที่ใช้ทำ pilot อยู่ที่ `D:\Download\furniture_dataset.zip` พบว่า **ภาพทั้ง 5,029 ภาพซ้ำกับ v2 ทั้งหมด ไม่ใช่ข้อมูลใหม่**

### งาน F: ยืนยันขอบเขตและเขียนรายงาน
- ถามอาจารย์ว่าขอบเขตหัวข้อรวม Style classification และ room pipeline หรือไม่ (ค้างมาตั้งแต่ checklist เดิม)
- รายงานต้องแยกผล 3 ชุดตามตารางด้านบน ห้ามรวมคะแนน synthetic test กับ real-source test
- ต้องระบุว่า annotation ของ source มาจาก Qwen2 VL 72B ไม่ใช่ผู้เชี่ยวชาญ และ confidence เป็น softmax ที่ไม่ได้ calibrate

## เทรนต่อ: ต้องรอ trigger จากงานด้านบนก่อน

| ถ้าทีมตัดสินว่า | ผลที่ตามมา | งานของผม |
|---|---|---|
| ใช้ผลปัจจุบันตามเดิม (A, B ข้าม) | ไม่ต้องเทรนเพิ่ม | ช่วยทำรายงาน/กราฟที่ยังขาด |
| ทำ A เสร็จ | ต้องสร้าง snapshot v3 และรัน screening → controlled → ablation → repeated ใหม่ | สร้าง snapshot, dry-run, ตรึง manifest แล้วเริ่มเทรน |
| เปลี่ยนนโยบาย style (B) | ต้องเทรนใหม่เช่นกัน | แก้ mapping และ config แล้วเทรน |

ข้อมูลต้นทางที่ใช้จริงในปัจจุบันคือ `data/furniture-v2-conservative` (ฝึก 5,956 / validation 1,295 / synthetic test 1,127 / real-source test 1,000) และ GPU ที่ใช้คือ RTX 4060 Laptop

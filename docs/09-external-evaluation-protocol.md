# External real-source evaluation protocol — v1

The source test manifest is an external reference set, separate from the synthetic
test and all training/development data. Do not use it for training, checkpoint or
model selection, label mapping decisions, or calibration. The released source
[dataset card](https://huggingface.co/datasets/filnow/furniture-synthetic-dataset)
describes test annotations generated by Qwen2 VL 72B and warns that annotations
may be inconsistent. It does not establish human or expert verification. Report
comparisons against **source annotations**, not expert ground truth. The source
revision and all previously excluded samples must be recorded by the snapshot;
inspection counts describe only rows included in the external manifest, not
excluded source records.

Class indices are created from the training manifest only, separately for type
and style. Matching uses the label strings as stored, without fuzzy matching or
canonicalization. An optional future canonicalization must be independently
specified with a versioned mapping and rationale before predictions and must not
be adjusted to prediction results. Empty labels are `missing`, labels present in
the training mapping are `known`, and the rest are `unseen`; these do not become
new class indices. Unseen does not mean that a model recognizes an unknown class.

The inspection reports missing, known and unseen counts and unseen label
frequencies per task, plus the number known for both tasks. For each task compute
closed-set metrics only on its known-label subset, reporting the eligible count,
total external rows and coverage. Joint correctness is the proportion for which
both predictions match their respective source labels, among the images known for
both tasks; report this numerator, denominator and coverage. Per-class and macro
metrics include all training classes, with zero division set to zero, so classes
absent from the eligible subset contribute zero. Retain separate case-level
missing or unseen records. Do not combine these metrics with synthetic-test
scores. No unknown-rejection result is claimed; any future rejection threshold
requires a separately designed calibration using development data only.

## Explicit workflow

The Python API is intentionally opt-in and computes no predictions when creating
the protocol:

```python
from furniture.external_evaluation import create_external_protocol, evaluate_external

create_external_protocol('snapshot/train.csv', 'snapshot/real_source_test.csv',
                         'results/external-protocol-v1.json')
# After screening/model selection, and only when external evaluation is authorized:
evaluate_external('results/external-protocol-v1.json', 'snapshot/train.csv',
                  'snapshot/real_source_test.csv', 'snapshot',
                  'selected-run/best.pt', 'results/external-v1')
```

Protocol creation freezes manifest SHA-256 hashes, training-only class mapping,
and annotation counts. It rejects overlapping train/external IDs, pixel hashes
or declared groups, and source-test rows in train. Evaluation verifies those
hashes and the checkpoint's training-manifest hash and mapping. It also rejects
any external pixel hash or declared group found in the checkpoint's train,
validation or test exposure membership; source IDs are checked when recorded.
Treating prior test membership conservatively protects against unknown past use.
The checkpoint must have complete exposure and initialization metadata; every
warm-start ancestor must be present at its recorded path with its recorded hash
and provide the same metadata, otherwise evaluation fails closed. Older project
checkpoints do not record source IDs, so the guard cannot compare those IDs and
uses pixel hashes and group IDs instead. It verifies the pixels of each external
image, and writes a new result directory with metrics,
predictions and a missing/unseen case file. The full snapshot audit must also
verify disjointness against validation and synthetic test, including reviewed
near-duplicate groups; train/external checks here are an additional guard, not a
substitute for that audit. Locked metadata cannot by itself prove the protocol
was written before some separate, independently generated prediction, nor prove
that a checkpoint was selected without external test access; these remain
research-process requirements. Actual training and source test evaluation are
not performed by creating a protocol.
